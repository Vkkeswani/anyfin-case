**Approach:** classify merchants, not rows. Bank text is normalised to a merchant key (Kortköp/AG/BG wrappers, purchase dates, store numbers, FX tails and KLARNA*/ZETTLE_*/SUMUP */IZ */PAYPAL * prefixes stripped), then structural rules (mirror-row transfers with savings detection, Swish person + message words, cash, interest, salary with an employer signal, card bills on both sides, refunds inheriting the merchant), then an exact lexicon of Swedish brands, then a weak lexicon of short tokens only trusted in brand position with a matching sign, and finally Claude Haiku 4.5 for the still-unresolved unique keys (40 per call, sign/account/amount context, answers cached per key+sign+account class).
**Cost:** validation 1,183 rows = 1 API call, ~1k tokens, $0.002, 2 s; stress run 5,517 rows with 458 unseen merchants = 12 calls, 38k tokens, $0.08, 20 s. At 10M rows/month with a warm cache (~0.5-2% new keys) that is roughly $10-50/month in LLM spend; parsing dominates runtime.
**Another day:** per-customer recurrence model (same payee, same day each month) as a second signal, a Sonnet second opinion for LLM answers in the 0.6-0.72 band, a held-out-customer harness to calibrate the cutoff, fuzzy matching for truncated merchant names.
**Run:** `pip install -r requirements.txt && ANTHROPIC_API_KEY=... python classify.py validation.csv -o predictions.csv` (train.csv in the same folder is used as a runtime merchant map; `--no-llm` runs rules and lexicon only).
**Abstention:** a wrong label costs a point and unknown costs nothing, so the system emits unknown for LLM answers below LLM_MIN_CONF=0.72, Swish messages outside a small unambiguous word list, large deposits without a salary/employer signal, transfers with no mirror row and no recognisable counterpart, and positive amounts at unrecognised merchants.
